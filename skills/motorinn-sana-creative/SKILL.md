## Brain Contract

When a generated creative asset is worth keeping, write a brain note that records:

- campaign or use case
- source prompt
- vehicle facts used
- generated file URI or published asset URL
- approval status
- expiration/retention expectation
- downstream use: social, email, ad, landing page, listing hero, or internal concept

Do not store every generated variant in brain. Store only selected assets, decisions, learnings, and reusable prompt patterns.

## Routing Rules

- Emily owns image prompt framing, visual QA, and design handoff.
- Rory owns captions, campaign facts, approvals, and publication.
- Use generated images as concepts/backgrounds, not literal inventory photos.
- Keep hard facts in copy and approval packets, not in generated pixels.
- Customer-level DealerVault campaign ideas must start from the review-first opportunity queue generated by `npm run marketing:generate-opportunities`.
- Daily social drafts are bridged into the existing clawd/Publer approval flow with `npm run marketing:generate-social-queue -- --from-athena --write-clawd-pending`.

## Retention Rule

Operational files expire through the SANA cleanup job. Brain should keep metadata and final-published URLs, not raw throwaway variants.

## Opportunity Memory Rule

Store the selected opportunity ID, campaign decision, approved prompt pattern, and final asset URL. Do not store raw customer exports or unapproved PII in brain notes.
